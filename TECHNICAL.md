## Processing raw files

From the flock directory containing all the sibling crates (for example, `/path/to/oolonek/isla-gabriola-flock`), replace the example input/output paths with your own paths before running these commands. Choose an output directory deliberately: a successful run **replaces existing outputs for its selected mode** for each processed file; other mode outputs remain untouched. Picoto extracts features independently from each centroided acquisition and writes a feature list, an acceptance/rejection audit, and derived spectra; an MS2 spectrum in an MGF output is not necessarily one unmodified instrument scan. See [Selection and provenance](#selection-and-provenance) for how scans are selected and combined.

```sh
cargo run --release --manifest-path picoto/Cargo.toml -- \
  /path/to/raw.mzXML /path/to/output
cargo run --release --manifest-path picoto/Cargo.toml -- \
  /path/to/raw-directory /path/to/output --jobs 2 --mode both
```

For a selected batch without copying raw files, create a UTF-8 text file at a path you choose, with one relative mzXML/mzML path per line, for example:

```text
pos/run.mzXML
neg/run.mzML
```

Then, from the flock directory, pass that file with `--files-from`:

```sh
cargo run --release --manifest-path picoto/Cargo.toml -- \
  /path/to/raw-directory /path/to/output --files-from /path/to/selected-files.txt --jobs 2
```

This option requires a directory input; only listed files are processed, using the same worker pool and mirrored output subpaths as recursive discovery. An empty list, duplicate paths (including aliases of one file), absolute or parent-traversing paths, invalid UTF-8, unsupported extensions, missing/non-file targets, and symlinks leading outside the input root are rejected before processing starts. Without `--files-from`, file and recursive-directory inputs behave as before.


A file or recursively searched directory is accepted. Directory subpaths are mirrored beneath the output directory; only `.mzXML` and `.mzML` files are processed. Output names for `run.mzXML` are `run_sirius.mgf` (default, paired MS1+MS2), `run_ms2.mgf` (`--mode ms2` or `--mode both`), `run_feature_list.tsv` (accepted features only, always), and `run_features.tsv` (acceptance/rejection audit, always). `--mode ms2` produces MS2-only MGF rather than the paired file. Existing outputs for a selected mode are replaced after successful per-file processing; outputs from previously selected modes are left untouched. A file failure does not prevent other files completing, but the batch exits nonzero. Jobs bound simultaneous file processing (`--jobs 4` by default). A terminal progress bar and per-file feature counts are displayed.

The feature list defaults to `feature_id`, `mz`, `rt_seconds`, `peak_height`, `peak_area`, `isotope_peaks`, and `quality_score`. IDs match the accepted audit rows and MGF feature IDs. Height is the apex MS1 intensity; area is the trapezoidal integral of the traced MS1 intensity over retention time (intensity·seconds), **not** a MZmine area. `isotope_peaks` counts observed +1/+2/+3 isotope peaks at the apex (not the monoisotopic peak); `quality_score` is the detector's ranking heuristic, `ln(1 + apex / max(minimum traced intensity, 1)) × (1 + 0.2 × isotope_peaks)`, not a probability or identification confidence. The audit prints this score to three decimals, whereas the feature list retains full precision. MZmine reference tables use minutes for RT and a different peak-picker, so neither coordinates nor areas need match exactly. Add `--metrics data-points,fwhm` to include `ms1_data_points` (number of traced MS1 scans) and `fwhm_seconds` (linearly interpolated width at half height above the trace minimum). Either metric may be requested alone; FWHM is blank if either half-height crossing is absent. Collecting FWHM retains time/intensity samples for active traces, increasing memory use; without it only trace summaries are kept.

```sh
picoto/target/release/picoto /path/to/run.mzXML /path/to/output --metrics data-points,fwhm
```

## Selection and provenance

The mzXML reader streams base64 peak pairs (32/64-bit, uncompressed/zlib); `mzdata` streams mzML peak arrays. Profile or unknown-polarity scans are rejected, not silently centroided or relabeled. MS1 centroids are linked over successive scans using the larger of `--ppm 10` or `--absolute-mz 0.003` Da. Separate chromatographic apices at the same m/z can split at a valley (≤40% of the preceding apex followed by a ≥50% rise). The default gate requires `--min-scans 3`, `--min-height 100000`, an apex-to-minimum intensity ratio of `--min-contrast 3`, a rising and falling trace, and a matched MS2 with at least `--min-ms2-peaks 3` signals above 1% of its base peak. `--max-ms2-rt-offset 20` seconds restricts precursor matching around the feature apex. These are **heuristic defaults**, not a validated chemical identification or signal-to-noise estimate. Check the audit table and adjust for the instrument and samples.

The isotope/correlated-MS1 block contains the monoisotopic apex peak and observed +1/+2/+3 isotope peaks, if present. Missing isotopes do not reject a feature; their count increases the audit `quality_score`, a ranking heuristic (not a probability). The detector retains up to `--max-ms2-scans 8` candidates near the current apex **and** up to eight more from the most recent acquisition window; this protects a later apex from having its MS2 scans evicted by earlier high-scoring scans. Only spectra within `--max-ms2-rt-offset` of the final apex can be exported. Scans can merge only with matching precursor/charge/polarity, collision energy (within 1 eV when recorded), and fragment cosine similarity ≥0.7; fragment alignment uses the larger of 20 ppm or 0.005 Da and never collapses distinct peaks from the same scan. Otherwise the best scan by informative fragment count and intensity is used. Native scan IDs and rejection reasons are recorded in the TSV; MGF `SCANS` and `MERGED_SCANS` contain numeric scan identifiers when available. Collision energy is retained in MGF. The per-file audit includes candidate traces observed in at least two MS1 scans or with an MS2 assignment; isolated single-scan noise is omitted.

Processing uses streaming raw readers, active trace summaries, and a capped MS2 candidate list, not a copy of every input spectrum. Parallel memory still increases with `--jobs`, active chromatograms, accepted features, and audit/output buffers. Files are processed independently: a blank sample is **not** used to filter a biological sample. Feature count alone is not a quality metric; compare audit scores and chromatograms before interpreting biology.

`--jobs N` runs up to N separate raw files concurrently; it does not speed up a single file. Each worker owns an input reader, feature state, and temporary audit/list/MGF outputs in its destination directory. More jobs multiply peak memory use and simultaneous disk reads/writes; large chromatograms, many accepted features, and `--metrics fwhm` increase per-file memory, while `--mode both` stages two MGF files per input until publication. Start with the default `--jobs 4`; try 8 only when available memory and input/output storage throughput allow it, and budget these workers alongside other pipeline stages. The progress bar counts completed files, including failures. After all files finish, successes are printed in input order to stdout and failures in input order to stderr; the batch exits nonzero if any file failed.

## Terminal inspection and comparison

The static `picoto view chromatogram|spectrum|features|feature` commands use optional [xan](https://github.com/medialab/xan) for terminal plots (`cargo install xan`). `picoto view interactive` uses Ratatui/Crossterm instead, with **no xan requirement**; raw processing and feature selection remain pure Rust. Raw retention times, exported tables, and static plot coordinates use seconds; the interactive RT axis displays minutes by default. Supply both `--rt-start` and `--rt-end` (seconds) to limit a static chromatogram; XIC uses the larger of 10 ppm or 0.003 Da unless overridden.

```sh
picoto/target/release/picoto view chromatogram /path/to/raw.mzXML --kind tic
picoto/target/release/picoto view chromatogram /path/to/raw.mzXML --kind bpi
picoto/target/release/picoto view chromatogram /path/to/raw.mzXML --kind xic --mz 343.1548 --rt-start 220 --rt-end 290
picoto/target/release/picoto view spectrum /path/to/raw.mzXML --scan 2193
picoto/target/release/picoto view features /path/to/output/run_features.tsv --plot map
picoto/target/release/picoto view features /path/to/output/run_features.tsv --plot intensity
picoto/target/release/picoto view feature /path/to/raw.mzXML /path/to/output/run_features.tsv FEATURE_ID
picoto/target/release/picoto view interactive /path/to/raw.mzXML /path/to/output/run_features.tsv --kind xic --mz 343.1548
picoto/target/release/picoto view interactive /path/to/raw.mzXML /path/to/output/run_features.tsv --kind tic
picoto/target/release/picoto view interactive /path/to/raw.mzXML /path/to/output/run_features.tsv --feature-list /other/path/run_feature_list.tsv
picoto/target/release/picoto view interactive /path/to/raw.mzML --kind bpi
picoto/target/release/picoto view interactive /path/to/raw-dir /path/to/picoto-output-dir
picoto/target/release/picoto view interactive /path/to/raw-dir /path/to/top_n_root/N/picoto
picoto/target/release/picoto view interactive /path/to/raw-dir/batch/run.mzML /path/to/top_n_root/N/picoto/batch/run_features.tsv
picoto/target/release/picoto view interactive /path/to/raw-dir
```

The feature map shows accepted audit rows by retention time and m/z; the intensity plot shows their MS1 apex intensities. `view feature` prints audit details and plots a ±30 s XIC around its apex plus its first recorded selected MS2 scan. `view spectrum` accepts a numeric scan number or native scan ID. Use the audit `feature_id` for `view feature`, not an MGF ion-block index.

The interactive viewer draws Braille-resolution TIC, BPI, or XIC (use `--kind bpi` for BPI). Its chromatogram has a numeric RT axis in **minutes** by default; `u` toggles display to seconds without changing scan selection or extraction. Click a **◆ accepted-feature marker** to load its nearest-RT raw MS1 scan and selected raw MS2 scan; press `1`/`2` (or `m`) to switch the lower spectrum pane. MS2 metadata shows the selected raw scan's precursor m/z and its charge when present (otherwise `precursor unavailable`); the feature m/z is not substituted for a missing precursor. Clicking elsewhere on the chromatogram loads the nearest MS1 scan, without inventing an MS2 association. Strong spectrum peaks and the numeric m/z axis are labeled **below** the sticks. Click a drawn stick to show its exact m/z and generate the corresponding MS1 XIC in the upper chromatogram. XIC extraction sums matching centroids in each MS1 scan within the larger of 10 ppm or 0.003 Da (unless `--ppm`/`--absolute-mz` was set); accepted-feature markers update for that m/z, including ones outside the starting XIC. A clicked MS2 fragment can produce a flat XIC when no MS1 signal exists at its mass.

With **only a raw mzML/mzXML path**, the viewer finds a same-stem `*_features.tsv` beside the raw file and automatically loads the matching `*_feature_list.tsv` if present. It does not inspect Mato job configurations: to view output stored elsewhere, supply the exact audit TSV for a single raw file or the output directory as the second argument. For a Mato top-N run, use its `top_n_root/N/picoto` directory, preserving the raw directory's relative subpaths; for a single nested raw file, pass its exact `*_features.tsv` path. Without an audit, raw TIC/BPI/XIC and MS1 inspection still work without picked features. A supplied picoto-named audit or list from a **different raw stem** is ignored, and a warning appears in the viewer; a matching adjacent output is used when available. Names alone cannot prove the contents of renamed/custom TSV files belong to a raw file.

For a directory, the viewer finds mzXML/mzML files recursively and opens a **raw-file sidebar** (`g` shows/hides it). The optional second argument is an audit TSV for one file or an output directory whose relative subpaths match the raw directory; `--feature-list` likewise accepts a TSV for one file or a matching directory. Without an audit for a given raw file, TIC/BPI/XIC and nearest-scan MS1 still work, but accepted-feature markers, picked-feature details, and linked MS2 are unavailable. `n`/`b` move to the next/previous file; arrows or `j`/`k` select a sidebar row, Enter opens it, and mouse clicks open rows. Newly visited files become visible automatically. Each file has a distinct colored swatch and chromatogram: Space toggles the highlighted file in the sidebar (or click its checkbox), and `o` toggles the active file even with the sidebar closed. `f` switches the right pane to the active file's picked features; `g` returns to raw files. `q` or Esc closes an open sidebar before exiting.

The overlaid chromatograms share **RT and absolute-intensity axes**; they are not normalized or aligned across samples. Zoom/reset affects all visible traces. MS1/MS2 spectra, precursor metadata, and accepted-feature markers always belong to the **active** file; switching files clears its previous spectrum and pinned MS2 reference. Clicking the chromatogram inspects only the active file; show its trace before clicking. An exact-mass XIC recomputes visible files at the same m/z in the background, hiding stale traces until each result arrives. The first file loads before the viewer opens; other visited files are cached in memory.

Both MS1 and MS2 spectra emphasize peaks at **5% or more of the highest intensity in the visible m/z window**; weaker centroids remain in the raw data but are not drawn, labeled, or selected by mouse. Brighter green denotes stronger peaks. Press unshifted `h` to lower the display cutoff (5% → 1% → 0%, showing all nonzero peaks), or `l` to raise it (10% → 25%); the current percentage appears above the sticks. These keys work on Swiss French layouts where `[` and `]` may not register. Changing the cutoff does not change XIC extraction or feature picking. When multiple masses occupy one terminal column, the taller stick remains visible and a click selects the strongest peak at that column.

Spectrum sticks default to Unicode one-eighth-block heights (`▁`–`█`), giving **eight intensity steps per terminal row**. Press `v` to switch to the previous thin `│` sticks, and again to restore fractional bars; both styles use the same peak cutoff, m/z labels, and mouse selection. The fractional tip is clickable. This changes only display resolution, not centroid intensities; fractional (especially downward mirror) bars need a terminal font with Unicode block glyphs.

Press `i` to color **candidate isotope daughter peaks** magenta in either MS1 or MS2; press again to hide them. The detector's charge-one spacing rule matches the nearest peak at +1/+2/+3 × 1.003355 Da within max(10 ppm, 0.004 Da) of each candidate parent. Coincident masses are not chemical identifications, and this overlay neither assigns charge nor changes feature picking, XIC extraction, or exported isotope counts.

To compare two feature-associated MS2 scans, load the first spectrum and press `p` to **pin** it, then select another feature's MS2 (◆, `Tab`, or sidebar `s`). The pinned reference is above the center line and the current MS2 below it, each scaled to its own visible base peak on the **same m/z axis**. Wheel zoom affects both spectra; clicking a stick in either half extracts its exact-mass MS1 XIC. `1` temporarily shows MS1 without dropping the reference; `2` restores the comparison. Press `p` again to unpin. Spectrum and sidebar frames use rounded terminal borders.

Press `f` to show the accepted-feature list **on the right**, with the chromatogram above the spectrum on the left. Its table shows ID, m/z, RT in the current display unit, peak height (MS1 intensity), peak area, isotope-peak count, and quality score. Missing optional measurements appear as `-`; the row values are abbreviated to fit, while full TSV values (including optional `ms1_data_points` and `fwhm_seconds`) and the selected raw MS2 scan ID appear **below** the rows. The viewer discovers `run_feature_list.tsv` beside `run_features.tsv` automatically; `--feature-list PATH` overrides that location. A missing list does not prevent chromatogram/spectrum inspection: `f` reports how to provide it. A present list must have the same accepted IDs and coordinates as the audit before associating raw MS2 scans. The sidebar needs at least 80×20 terminal cells; narrowing the terminal hides it but leaves the plots available. The feature sidebar uses up to 50 columns to keep all seven values visible; close it with `f` for a wider plot. Left/right arrows or the mouse wheel over details scroll long records.

Click a different feature-table header to sort its column **ascending**; click the active header to reverse its direction. The sort column and arrow appear in the table border (ID starts ascending). Measurements sort numerically, not alphabetically; missing values stay last in either direction. Sorting keeps the current search filter and changes which row is selected; the detail pane, XIC, and MS2 actions follow the newly selected feature.

In the sidebar, press `/` and type a case-insensitive substring to search **every** TSV column; use `column:value` to search one named column, for example `mz:343.154`, `quality_score:8.9`, `ms1_data_points:49`, or `fwhm_seconds:2.268`. Results update as you type; Enter finishes editing, Esc stops editing, and `c` clears the filter. Up/down arrows or `j`/`k`, PageUp/PageDown, Home/End, and mouse clicks select a result. Enter or `x` extracts its full-precision MS1 XIC, focuses RT around its apex (±30 s), and shows nearest MS1; `s` or `2` loads its associated MS2. **The sidebar stays open** so you can compare features with the changing plots. Mouse clicks and wheel zoom on the left plots, `+`/`-` RT zoom, `h`/`l` intensity emphasis, `1` for MS1, and `m` for MS1/MS2 switching still work while it is open. `f`, Esc, or `q` closes only the sidebar; background readers keep input responsive.

With the sidebar closed, press `/` to enter a numeric exact-mass target (for example `343.15480712`), then Enter to extract its MS1 XIC without selecting a spectrum peak or using a mouse. Backspace edits; Esc cancels the entry without leaving the viewer. Invalid or nonpositive m/z remains editable. The typed m/z is the extraction center, **not** rounded or snapped to an observed peak; the existing ppm/absolute-Da tolerance still determines which raw MS1 centroids contribute. The full-precision target is shown in the chromatogram title.

Press `t` to leave an XIC and return to the **full chromatogram**: TIC by default, BPI if opened with `--kind bpi`, or TIC if opened with `--kind xic`. This restores the full retention-time range and recomputes enabled file overlays in the background; the selected spectrum stays available. `t` also cancels a still-pending XIC when the full trace is already shown. The key works with either sidebar open, except while entering a sidebar search.

Press `+`/`-` or scroll over the chromatogram to zoom retention time; scroll over the spectrum to zoom m/z around the cursor and resolve nearby peaks. `r` resets both zoom ranges without changing the current XIC. `Tab`/`Shift-Tab` cycle visible accepted features; right/left arrows also cycle them when the sidebar is closed. `q` or Esc exits when neither sidebar nor mass entry is active. Spectrum and chromatogram extraction run in separate background workers, so zoom/selection remains responsive while raw files are scanned; pending scan and chromatogram selections are coalesced and outdated results ignored. Rendering bounds dense chromatograms to screen-resolution buckets while preserving local intensity extrema. Large files may still take time to decode for each new spectrum or chromatogram, and the first chromatogram is loaded before the viewer opens. Interactive memory retains chromatograms and picked-feature metadata for visited files plus the selected MS1/MS2 scans, not every raw spectrum; it grows with files visited. A terminal with mouse-event support is needed to click peaks; keyboard controls, including exact-mass search, work without one.

The [six-file overlap plot](evaluation/coordinate-overlap.svg) and [quality-score distribution](evaluation/quality-distribution.svg) live in this repo. Regenerate them and the one-to-one comparison summary with `python3 picoto/evaluation/compare.py --reference-dir /path/to/msdata/processed --picoto-dir /path/to/picoto-output` (requires NumPy, SciPy, matplotlib). The script matches distinct features within `max(0.003 Da, 10 ppm)` and 15 s, with maximum matching cardinality followed by minimum coordinate error. MZmine is a comparator, **not** ground truth: extra picoto features require inspection, especially on blanks.

## Verification and boundaries

CLI tests cover paired chromatographic features and their height/area list, optional traced-point count and FWHM (including an absent crossing), separated apices at one m/z, compatible/incompatible MS2 scans, close-fragment preservation, optional MS2-only output, parallel recursive batches, rejected traces, profile rejection, and later-apex MS2 retention under a tight candidate cap. The [six-file overlap plot](evaluation/coordinate-overlap.svg) and [quality-score distribution](evaluation/quality-distribution.svg) illustrate a comparison on Zenodo record 10018590; MZmine files are a comparator, **not** exact expected results. This small illustration does not establish throughput on many thousands of files.

Feature-list unit tests cover generic searches across optional columns, named-column filtering, row-to-audit/MS2 mapping, and rejection of stale coordinates. The viewer has also been inspected with optional metrics, a filtered raw MS2 scan and a full-precision m/z XIC at different terminal sizes.

Paired MGF has been generated and inspected, but **end-to-end SIRIUS ingestion remains unverified**: a SIRIUS 6.3.3 CLI attempt could not run with an expired authorization token (`invalid_grant`). No credentials are needed to run picoto itself.
